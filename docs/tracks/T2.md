## T1 caveats re-checked against k4o main (bdfb838)

| T1 caveat | Holds? |
|---|---|
| Filter args see top-level data only, never `{% set %}` vars or loop props | **No.** `link:s.name`, `fragment_link:s.url`, `wikilink:` with loop vars all resolve now (the F1 fix landed). Exception: a `{% set %}` var defined *inside* a loop is still taken literally as an arg |
| Callout tuples take literals only | Mostly: a variable *title* now works (`callout:("note", label)`); a variable *kind* is still a syntax error |
| `a ?? b \| f` parses as `a ?? (b \| f)` | Yes. And `(a ?? b)` with parens is a syntax error |
| `x \| wikilink \| list` escapes the brackets in markdown | **No.** `- [[Alpha]]` renders clean now |
| Missing key as a bare filter arg becomes a literal | Yes: `link:missing_key` renders `[missing\_key](text)` with no diagnostic |
| `yaml_property` on a missing key emits `key: null` | Yes (optional frontmatter keys are all behind `{% if %}`) |

New quirks found on main:

- **`link` argument order is `url | link:"text"`** (value is the URL, arg
  is the link text). T1's templates use the reversed form in two places
  (`changelog_url | link` in release-notes, the "read it free" link in
  reading-note); on main those render as `[https://...](Full%20changelog)`.
  T1 should swap them.
- **`fragment_link` only links arrays of two or more items.** A bare string
  or a 1-item array passes through unlinked. The templates pad with
  `merge:""`, link, then unwrap with `first`. T1's single-quote callouts
  lose their deep links on main.
- **Unbalanced `)` in quote text is not percent-encoded** in the text
  directive (balanced parens are fine). Samples avoid stray parens.
- **Singleton arrays collapse to scalars in filter chains.** `footnote` on
  a 1-item array emits plain text; `map:"name" | wikilink | yaml_property`
  on one source emits a scalar, not a list. Object-keyed footnotes sidestep
  the first; the second is why the verdict frontmatter guards
  `{% if sources %}` only.
- **`{{ rows | table }}` emits single-dash delimiter rows (`| - |`)** in
  markdown, which no renderer accepts as a table, and takes headers from
  object keys, which prevents per-cell wikilinks and footnote refs. The
  templates hand-write pipe tables with `---` delimiter rows; dogbed
  `d7ffaba` (#33) renders those as real `<table>`s in html.
- **dogbed renders YAML frontmatter as `<hr>` + visible text** in html; the
  key/value lines show up in the page. dogbed issue, affects all templates.
- dogbed `d7ffaba` bundles k4o `122f161`, which has a cosmetic bug: inside
  a `{% for %}` loop, with multibyte data (an em dash in a source name),
  one space around the output is dropped (for example `</a>· `). Shows up
  in the html sources list only; markdown is unaffected.
- dogbed resolves `[[wikilink]]` hrefs to the percent-encoded page name
  (`<a href="AcmeDB%20docs%20%E2%80%94%20backups">`). Fine for a local
  render; published-site resolution is boris's job.
- **Whitespace:** text right after an opening tag, or after an inline block
  that rendered nothing, loses its leading space. Inline conditionals
  always take a branch (`if`/`else`) and keep spaces outside the tags.
  Untaken standalone `{% if %}` blocks leave stray blank lines; the idiom
  used here is `{% if x %}{{ "" }}` on the block's first line with a
  standalone `{% endif %}`, which yields exactly one blank separator either
  way. `{%- if %}` is an "empty logic tag" error. `{% if xs | length > 1 %}`
  is a syntax error (no comparisons on filtered values).
- **`{% if a != b %}` works** and powers the apparatus back-link.
- `wikilink:` with an empty arg and `footnote:"1"` are silently accepted
  (why those eval seeds are no-ops; a P1 engine gap, not template bugs).
