## Site resolution

`KNAP_BORIS_SITE`, else `<templates_dir>/../../boris-site` (the same rule as
B2). From the built binary that resolves to the repo's `boris-site/` from
any working directory. A missing file fails with `cannot read
<site>/artifact/<file> (set KNAP_BORIS_SITE ...)`. A wrong `format` or
`schema_version` fails with, for example, `search-index.json: unsupported
format "boris-rendered-search-index", schema_version 2 (want
"boris-rendered-search-index", 1)`. `schema_version` must be the number 1,
as in `ask.sh` (`"1"` is rejected).

## boris_ask: the `ask.sh` port

Output `{"query","results":[{"score","id","path","fragment","title","heading","snippet"}]}`.
`results` is `ask.sh -k N` output, element for element. Details that had to
be matched and are easy to get wrong:

- **Whitespace is Unicode.** jq's `\s` (Oniguruma) matches Unicode
  White_Space: U+0009-000D, U+0020, U+0085, U+00A0, U+1680, U+2000-200A,
  U+2028, U+2029, U+202F, U+205F, U+3000. Not U+001C-001F, U+200B, U+FEFF.
  Verified against jq 1.8.2 one codepoint at a time. Lowercasing is ASCII
  only.
- **In-page ties keep the last section.** jq's `max_by` replaces on `>=`,
  so among equal-scoring sections the later one wins (the `"the"` and `"a"`
  queries hit this). Across pages: score desc, then path bytes, then
  section index.
- **Duplicate query terms count twice** (`split(" ")` without dedupe).
- **Snippets are codepoint windows.** jq 1.8 `index` and string slices count
  codepoints: anchor at the first term *in query order* (not the earliest
  position) found in the ASCII-lowercased source, start 48 codepoints
  before it, take 150, add `…` on each truncated side. The source is
  `text`, else `code`, else `heading`, whitespace-collapsed but not trimmed.
- `limit` 0 gives no results. Negative or non-integer limits are an error
  (MCP takes an integer, the CLI flag a string; both are accepted).

## boris_check: the decision

Output `{"claim","answer","verdict","polarity","coverage","matched":{"id","title","verdict","cites":[{"id","title","url"}]}|null,"reason"}`.

1. **Terms.** Split the claim into ASCII words (`[a-z0-9]` runs with
   interior `-` and `'`; U+2019 counts as `'`). Drop stopwords (80
   function words, list in `borisrag.zig`) and negation cues. Plural-fold
   (`'s`, then one trailing `s` but not `ss`, on words over 3 bytes).
   Drop terms that are on every claim page: today `acmedb`, plus the
   section headings `claim`, `verdict`, `evidence` and `the`. This is
   computed from the artifact, not hard-coded, and only applies with two
   or more claim pages.
2. **Coverage** of a claim page = matched terms / terms, against the folded
   words of its title and every section, including the parts of
   hyphenated words. Rounded to 4 decimals.
3. **Match** = the claim page with the highest coverage; ties go to the
   `ask.sh --claims` rank, then document order. A pure retrieval top hit
   was not enough: titles all contain "AcmeDB", and `ask.sh` substring
   terms keep their punctuation (`backups?`). If no claim page has a
   retrieval hit and coverage is 0, `matched` is null.
4. **Coverage < 0.5**: `answer` unknown, `verdict` and `polarity` null,
   `matched` still set, `reason` lists the missing terms.
5. **Polarity**: `opposite` when exactly one of the claim and the matched
   title has a negation cue (`no`, `not`, `never`, `without`, `lacks`,
   `missing`, any `…n't`, plus `cannot`, which the brief did not list).
6. **Answer**: supported+same yes, supported+opposite no, refuted+same no,
   refuted+opposite yes, unverified unknown. A verdict tag outside those
   three gives unknown with `verdict` null.
7. **Cites**: each `cites` relation, titled from `completion.json`, URL from
   the cited page's level-1 section text (`URL: <non-space run>`), else null.

Top-level `verdict`/`polarity` are the basis of the answer and null when
none was reached. `matched.verdict` is always the page's tag.

### Known misses (in `claims.json` as `known_miss`, not gating)

The polarity rule sees negation words only, not antonyms or paraphrase:

| Claim | Truth | Gives | Why |
|---|---|---|---|
| Does AcmeDB have cross-region replication? | no | yes | Matches "AcmeDB is single-region only" (supported); no negation word on either side |
| Does AcmeDB run in multiple regions? | no | yes | Same claim page, coverage 2/3 |
| AcmeDB never loses acknowledged writes | yes | no | "never" flips polarity against "acknowledges only durable writes" |

Fixes, if wanted: polarity against the claim page's `## Claim` sentence
as well as the title (it says "There is no cross-region replication"), or a
`judge` pass through `backend.complete` for answers with coverage under 1.
Neither is in this PR. The gate prints `FIXED` if a known miss starts
passing.
