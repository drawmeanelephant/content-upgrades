# Track C1: the `knap_voice` tool

`knap_voice` rewrites the `voice: true` string values of a data object in
one tone. It makes one model call per value and keeps a rewrite only if it
passes the fact guard. The template never changes, so every tone renders
with the same structure. It follows C3's contract in
`knap-mcp/prompts/voice/README.md`.

## What landed

- `src/voice.zig`: the logic.
  - Eligibility walk over `templates/shapes/<id>.json`: `string`,
    `array<string>` (role gets ` (one item)`), and the `fields` of every
    `array<object>` element (`breaking[0].fix`). Values that are empty or
    multi-line are skipped.
  - The README's "Never rewritten" list, enforced in code whatever a shape
    says (`neverRewritten`): ids, URLs (`url`, `*_url`), wikilink targets,
    enums, dates and numbers, `frontmatter`, `receipts`, verbatim
    quotes/claims, page-name fields, `note`/`notes`/`tags`/`status`, the
    tables, and `title` for apparatus and reading-note.
  - Call assembly that is byte-identical to `assemble.sh` (`assembleSystem`,
    `userMessage`), plus reply cleaning (`cleanReply`).
  - A Zig port of `voice.awk`'s guard (`guard`). `Check.hard` holds hard
    rules 1 to 6 plus profanity in a mild reply; any entry keeps the
    original. `Check.budget` holds the other tone budgets, which only warn
    at runtime. check.sh treats every reason as a failure, and so does
    `Check.strict()`.
  - Mock: looks up `prompts/voice/mock/<tone>.jsonl` by (template, field,
    input). A miss leaves the value unchanged. The guard runs on mock
    replies too.
  - Live: `backend.complete(ctx, kind, .voice, system, user)`, once per
    value. With no `MODEL_API_KEY` the tool fails up front. A failed call
    marks that field `rejected` with `backend error: ...` and the pass
    continues.
- `src/tools/voice.zig`: the MCP handler. Input `{template_id, data, tone,
  backend?}`. A missing or unknown tone is an error, and so is an unknown
  backend. The default backend is `ctx.backend_kind`.
- CLI: `knap-mcp voice <id> [-d <file|->] --tone <t> [--backend <b>]`, with
  `"tone"` in `tool_flags` and a `--tone` help line.
- `prompts/voice/mock/*.jsonl`: 27 new lines per tone, covering every voiced
  value in `release-notes.sample.json` (15) and `reading-note.sample.json`
  (12). All 99 mock replies pass the guard and the tone budgets. I checked
  them by hand against `feral.md`'s safety line: they roast the product,
  never a person.
- `prompts/voice/testdata/system.{mild,spicy,feral}.txt` and
  `user.take.txt`: the `assemble.sh` goldens. `check.sh` now fails if they
  are stale. The README lists them and has the new counts.

## Entry point for later lanes

```zig
const voice = @import("voice.zig");
const r = try voice.voiceData(ctx, "verdict", data_json, .spicy, .mock);
// r.data: std.json.Value, the voiced object (key order and every other
//         value preserved; numbers are kept as unparsed number strings)
// r.changed, r.rejected(), r.fields[i].{field,before,after,status,reasons}
try r.write(&out.writer); // the knap_voice JSON, keys in contract order
```

`voice.parseTone("feral")` maps a name to a `Tone`. `voice.guard(a, tone,
role, input, reply)` is usable on its own, for example by a ratchet that
proposes its own rewrites.

Output: `{"template_id","tone","backend","changed","data","fields":[{"field",
"before","after","status":"rewritten"|"unchanged"|"rejected","reasons"}]}`.
A reason that starts with `warning: ` is an advisory budget overrun.

Prompts are read at runtime from `$KNAP_PROMPTS_DIR/voice/`. The default is
`<templates_dir>/../prompts/voice/`.

## For other lanes

- **P1 (backend.zig)**: `complete` already sends `temperature: 0`. A voice
  reply is one line, so a `max_tokens` cap (say 512) for `.voice` would
  bound cost and runaway replies. Nothing else is needed.
- **T2**: if verdict or apparatus sample values change, refresh the matching
  mock lines (check.sh warns about stale inputs). Then regenerate the
  goldens only if the examples change. A Zig test asserts that each
  sample changes in every tone with zero rejects.
- **C2**: `knap-mcp voice <id> -d <file> --tone <t> --backend mock`, then
  read `.data`. Every sample now changes in every tone.
- **Captain / docs**: `knap-mcp/README.md` could list the `voice` command
  and the `KNAP_PROMPTS_DIR` variable. I didn't add an Environment line to
  `usage_tail` because the brief allowed only the `--tone` line.
- **Numbers**: `voiceData` keeps numbers byte for byte, but the CLI's
  `readData` and `common.requireData` parse data with default options
  first. So a float like `1.50` reaches the tool already re-encoded.
  Integers, which is all the samples use, are unaffected.
