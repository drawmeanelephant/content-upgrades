## How it works

1. **Slots.** A slot is a top-level shape field with an `apparatus` key whose
   type the ratchet can grow (`string`, `number`, `array<string>`,
   `array<object>`, `array<array<string>>`), and which is `optional` or has
   a `max_items` bound. A required array grows only when the shape bounds
   it (reading-note `quotes`, `max_items: 5`). Required scalars are never
   empty, so they never grow. `object<…>` maps (`notes`) aren't v1 slots:
   filling one needs a nested write. The path is `name` for a scalar and
   `name[+]` for an append.
2. **Probes.** Every growable slot gets a shape-typed stub: the first enum
   option, `https://example.com/probe` for image and link slots,
   `Probe page` for wikilink and embed slots, otherwise `words` × `probe`.
   An `array<object>` stub fills the item's required fields. A table row
   matches the existing row width, else `cells`. Each probe is rendered to
   markdown and scored. Candidates are sorted by gain, ties broken by shape
   order.
3. **Ask.** For the best `top_k` candidates: mock reads the next canned
   value; live calls `backend.complete(ctx, kind, .enrich, enrich_prefix,
   slice)`. Both go through the same reply parser (trim, strip a fence,
   parse JSON; `null` means declined).
4. **Judge, in order:** schema → inert → verifier (evidence slots only) →
   server-side write → render → score. A value is accepted only if the
   score rises by at least ε and no format_check rule fires more often than
   before. Rejected values never touch `best`, so scores only go up.
5. **Stop:** `ceiling` (best is within ε of the ceiling), `plateau` (no probe
   gains ε), `stalled` (both asks rejected), `max_iterations`, `budget` (10
   calls).

Example live slice (`KNAP_DEBUG=1` prints it), reading-note min, first ask
(1016–1134 bytes, cap 4096):

```text
FIELD: aged[+]   (append one item)
SCHEMA: {"type":"array<array<string>>","optional":true,"apparatus":"table","max_items":5,"cells":3,"words":3}
ROLE: pipe table; first row is the header: [...]. Every row has 3 cells; no | or newlines in cells
HEADLINE: {"title":"The Machine Stops","source_url":"…","verdict":"read it tonight","gaf":"high","take":"…","bottom_line":"…"}
EVIDENCE: ["Imagine, if you can, a small room, …","I see something like you in this plate, …", …]
```

`SIBLINGS:` is added for arrays that already have items, and `TONE:` when a
tone is passed. With no `MODEL_API_KEY`, a live backend fails up front with
`backend 'spark' needs MODEL_API_KEY`, before any render.

## Where this differs from the plan, and why

- **Ceiling.** The plan computes the ceiling by stubbing every slot at once.
  That overshoots into the density curves' overload decay: reading-note's
  all-stub render scored 47.3, while the loop reaches 63.4 (both measured
  before P1's link fix). As written, the
  loop stopped with `ceiling` after one step. The ceiling is now the same
  greedy probe policy run with stub values for up to `max_iterations` steps
  (`stubCeiling`). It costs about half of each run's renders (see probe
  cost).
- **Inert tokens.** On top of the plan's list, values also reject `**`,
  `__`, `~~`, `==`, any backtick, any `|` (a pipe inside a table cell breaks
  the table), newlines (a value is one paragraph), and a leading `- `,
  `* `, `+ `, `1. ` or `> `. Each of these lets a value raise its own score
  or reshape its block.
- **Shape keys.** Two small additions: `cells` (table row width, so the
  first appended row is schema-checked before any row exists), and `link`
  in the `apparatus` vocabulary (`docs_url`). `image` and `link` slots must
  be http/https URLs.
- **Evidence pool.** With `evidence: "data"`, the pool is
  `data.sources[*].quote` (or `.text`, or bare strings), as the plan says.
  T1 data has no `sources` key, so the `.min.json` files carry one. An
  evidence slot with an empty pool is rejected as `verifier: no-evidence`.
- **Verifier.** M2 merged while this lane was open, so the evidence gate is
  `verifier.checkCitation(ctx, kind, claim, evidence)` (default
  `heuristic`). Every evidence-flagged string must come back `entails`; for
  the heuristic that means a normalized verbatim quote of one evidence item.
  Any other label is a `verifier` rejection with detail `<label>:
  <reason>`. `--verifier none` (or `"verifier":"none"`) skips the gate, and
  `decision` passes through to M2. The accept rule (gain ≥ ε, no
  format_check rule firing more often) stays in `ratchet.zig` rather than
  M2's `judgeStep`: it counts per-rule hits, while `judgeStep` compares rule
  sets.
- **Kept as written, but worth changing:** `top_k` retries the second
  candidate even when its probe gain is below ε. In the corpus that wastes
  one call on `tags[+]` (gain 0) in `adv-no-gain-wall` and one on
  `callouts[+]` (gain 0) in `adv-verifier-paraphrase`. Filtering
  candidates below ε before asking would save those calls. It's a one-line
  change; I left the algorithm as specified.

## Probe cost (measured)

Apple M4, k4o `bdfb838`, on a machine shared with other agents.

| Run | renders | of which ceiling climb | wall (Debug knap-mcp) | wall (ReleaseFast knap-mcp) |
|---|--:|--:|--:|--:|
| release-notes min → 71.8 | 76 | 39 | 216–321 ms | 151–158 ms |
| reading-note min → 68.4 | 80 | 41 | 221–295 ms | 136–150 ms |
| full corpus, mean per run | 39.7 | — | 115–139 ms | 72–77 ms |

A bare `k4o render` of release-notes costs about 2.5 ms from Python (50
runs), so k4o subprocesses account for nearly all of the wall time. Scoring
is about 0.03 ms per doc. The plan's estimate of "8 slots × 6 iterations ≈
48 renders" holds for the loop itself (about 37 renders); the ceiling climb
roughly doubles it. If latency matters in the demo, the ceiling climb can
reuse the loop's first probe round (they are identical), or be skipped by
passing a precomputed ceiling.

## Template v2 changes I'd want (plan 2.3), for P1 / T2

Measured on k4o `bdfb838`. I didn't edit any `.knap` file.

1. ~~`link` argument order~~: fixed by P1 (#24) before this PR merged.
2. **`fragment_link` drops the URL** in the quote callouts (`q.text |
   fragment_link:source_url | callout:…` renders the bare text), so
   `fragment_links` scores 0 on both templates. Once it emits the
   `#:~:text=` link, a quote gains about +4. That makes reading-note
   `quotes[+]` (the evidence-gated slot) a real ratchet step, so the
   verifier gets exercised on a shipped template rather than only the eval
   fixture.
3. **Block separation.** An optional image directly followed by the TL;DR
   callout renders with no blank line between them (`![…](…)\n> [!tip]`),
   and the same happens to table → h2 and list → h2. These don't cost
   points today, but they merge blocks for other markdown readers.
4. **Footnotes as a ratchet step** need a nested write: append a `notes` key
   and set a `note` ref on an existing highlight or quote. v1 doesn't do
   nested writes (captain's scope). A v2 `object<string,string>` slot
   ("append one key") plus `ref` integrity is the cleanest way to get there.
   It's the single biggest remaining signal (+12).
5. **verdict / apparatus** (T2): annotate after T2 merges. The ratchet only
   needs the new keys on those two shape files. An enumerated callout kind
   (plan 2.3 item 2) works on k4o main as an `{% if c.kind == "…" %}
   {% elseif %}` chain; see `eval/ratchet/callouts.knap`.

k4o main whitespace, for template authors: a newline right after a block tag
is eaten, and a block tag at the start of a line also eats the newline before
it. A blank line before a callout inside a `{% for %}` therefore takes four
newlines after the `for` tag (see `eval/ratchet/callouts.knap`).

## For other lanes

- **M2 (verifier):** the ratchet calls `verifier.checkCitation` for evidence
  slots and accepts `entails` only.
- **B3 (`boris_ask`):** `knap_ratchet` rejects `evidence: "boris"` with a clear
  message today. To add it, fill `Run.evidence` from `boris_ask` snippets
  instead of `dataEvidence`.
- **C1 (voice):** the shapes gained keys, but `voice` flags are unchanged.
  `knap_ratchet` never rewrites a non-empty value, so it composes with voice
  in either order. Reusing `ratchet.buildSlice` for voice slices would keep
  them under 4 KiB too.
- **P1:** `ratchet.zig` renders with `engine.render(ctx, .markdown, …)` only,
  so the target switch doesn't affect it. `backend.Task` gained one line
  (`enrich`).
- **I3 (model matrix):** `knap-mcp ratchet-eval --backend spark|wonder|baseten`
  is the values-only matrix. The adversarial cases rely on mock overrides,
  so on a live backend only the first four rows (min and sample) and the
  fixture row are meaningful; filter the rest out or move them to a
  mock-only corpus.
- **Captain / README:** new commands `density`, `ratchet` and `ratchet-eval`,
  new tools `knap_density` and `knap_ratchet`, the `--max-iters` flag, and the
  `apparatus`, `max_items`, `words`, `cells`, `evidence` and `ref` shape keys
  need a README mention. `knap-mcp/README.md` was not edited.
