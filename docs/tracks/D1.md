# D1: density scorer core

The deterministic formatting-density score: `knap-mcp/src/density.zig`. It
uses no model, runs natively, and takes about 0.02 ms per doc in ReleaseFast
and under 0.2 ms in Debug.

## API

```zig
const density = @import("density.zig");

const sc = try density.score(arena, markdown); // !density.Score
try density.writeJson(sc, writer);            // *std.Io.Writer
```

- `Score` has `total` (0–100), `words` (prose words, with frontmatter and fenced
  code excluded), `signals` (one row per spec, then one per format_check rule),
  and `warnings` (the raw `formatcheck.Warning`s).
- `Signal` has `name`, `raw` (the count), `value` (the count after length
  normalization, which is what the curve sees), `normalized` (0–1), `weight`,
  and `contribution` (`normalized * weight`). The contributions sum to
  `total` before it is clamped to 0–100.
- `writeJson` emits `{"scorer":"density/1","total":..,"words":..,"signals":[..],"warnings":[..]}`
  at fixed precision, so the same doc always gives byte-identical JSON.
- `density.version` is `"density/1"`. Any change to the tuning tables bumps it.
- Everything is allocated in the arena you pass in. Free the arena as a whole.

## How a score is built

1. **Counting.** A block pass over the lines, then an inline pass over each
   block's text, recognizes the following. It is a consistent approximation
   of CommonMark, GFM, and Obsidian syntax, not a full parser.
   - frontmatter and its top-level properties
   - ATX headings
   - quotes, and callouts: `> [!type]` blocks count only if they have a body line
   - pipe tables and HTML `<table>` (k4o's `markdown` target emits HTML tables, `gfm` emits pipe tables)
   - code fences
   - lists (counted as blocks, not items)
   - footnote definitions, and `[^id]` refs (only resolved ref/def pairs count; `^[inline]` notes count as resolved)
   - styled runs: bold, italic, code, strike, highlight
   - wikilinks, embeds and images
   - links: `[x](url)`, `<url>`, `[x][ref]`
   - deep links: any link destination with a `#`, including k4o `fragment_link`'s `#:~:text=` form
   - bare URLs
2. **Normalizing.** Counts become per-1000-word rates, using a 200-word floor
   so a stub with one table doesn't read as 25 tables per 1000 words. Styled
   coverage is styled alphanumeric characters over prose alphanumeric
   characters. Variety, level, and property counts are used as-is.
3. **Plateau curve.** Each signal's credit ramps linearly to its full weight
   at `sat`, holds through `over`, then decays linearly to 0 at `zero`.
4. **Noise tax.** Each positive signal past its `over` threshold also counts
   toward `overload`, which costs up to −20.
5. **Penalties.** Bare URLs scale up to −6. Each format_check rule deducts a
   fixed number of points per warning, up to a cap per rule. A doc with no
   warnings never loses penalty points.

All weights, thresholds, and penalties live in the `specs` and `penalties`
tables at the top of the file. A comptime check enforces that the positive
weights sum to 100.

| Group | Signal (weight) |
|---|---|
| Apparatus (63) | callouts 11, footnotes 12, tables 10, wikilinks 7, embeds 4, fragment_links 4, links 6, frontmatter 6, code_fences 3 |
| Typography (18) | styled_runs 5, styled_coverage 6 (full credit from 8% to 30%, none at 60%), emphasis_variety 4, blockquotes 3 |
| Structure (19) | heading_levels 3, heading_density 4, lists 4, block_variety 8 |
| Penalties | raw_urls −6, overload −20, format_check: skipped-heading 2/6, wall-of-text 4/8, unresolved-footnote 3/9, unused-footnote 2/6, empty-callout 3/9, raw-url-count 2/2, unclosed-fence 5/5, heading-ratio 4/4, list-heavy 4/4, other 2/6 (per hit/cap) |

## Calibration fixtures (`knap-mcp/eval/density/`)

Rendered with k4o `f97c5db`. Provenance is in `eval/density/README.md`.

| Fixture | Class | Words | Total | Main contributors | Penalties |
|---|---|--:|--:|---|---|
| `flat-barf.md` | wall, header, wall | 357 | **7.5** | headings and paragraphs only | — |
| `confetti.md` | over-formatted | 72 | **14.5** | tables 10, block_variety 8, frontmatter 4.5 (callouts, styled_runs, styled_coverage decayed to 0) | overload −15, raw_urls −6, raw-url-count −2 |
| `generic.md` | clean but generic | 227 | **18.8** | styled_runs 4.4, heading_density 4, lists 4, block_variety 4 | list-heavy −4 |
| `apparatus.md` | rendered template | 51 | **24.7** | wikilinks 7, styled_coverage 6, styled_runs 5 | raw_urls −6, skipped-heading −2, raw-url-count −2 |
| `verdict.md` | rendered template (HTML table) | 132 | **33.0** | tables 10, block_variety 8, wikilinks 7, frontmatter 6 | raw_urls −6, unused-footnote −4, raw-url-count −2 |
| `verdict.gfm.md` | rendered template (pipe table) | 132 | **33.0** | same | same |
| `cunty.md` | dense ideal | 193 | **97.0** | every positive signal at full credit except code_fences | — |

`zig run -OReleaseFast` scored all 7 fixtures in 0.13–0.20 ms across runs; a
Debug build took 1.17 ms. The unit test asserts under 50 ms.

The unit tests assert:
- `flat-barf < generic < verdict < cunty`
- `flat-barf < apparatus`
- `confetti < verdict`
- `|verdict.md − verdict.gfm.md| ≤ 2`

They also cover each signal's detection, the curve, stacked callouts scoring
lower, length normalization (a doc repeated twice scores within 1 point of
the original), deterministic JSON, and unmatched markers staying linear.

The fixtures show the headroom: the shipped verdict template scores 33, and
the same content with full apparatus scores 97. The verdict's gap is honest.
It has no callouts, its footnotes are defined but never referenced (k4o's
`footnote` filter emits definitions only), and its source URLs are bare.

Regenerate the table with:

```sh
cd knap-mcp
zig run -OReleaseFast --dep density -Mroot=eval/density/table.zig \
    -Mdensity=src/density.zig -- eval/density/*.md
```

## For other lanes

- **D2 (`knap_density` / `knap_ratchet`):** call `density.score(ctx.arena, doc)`
  and `density.writeJson`. Score `markdown` or `gfm` renders only, because
  textile uses different syntax. The two targets score the same apart from
  the table syntax. Use an epsilon when comparing totals in the ratchet. There
  is no tool and no CLI command yet, per the lane brief.
- **S0 registry:** this PR adds `_ = @import("density.zig");` to the test
  block in `src/main.zig`. `density.zig` calls `formatcheck.check`, so its
  tests pull in `formatcheck.zig`'s tests too. That depends on #13, which
  moved those tests onto an arena; before it they leaked and failed the run.
- **T2 / templates v2:** the cheapest density gains on `verdict` are footnote
  ref slots (+12, and −4 penalty gone), a callout (+11), sources as links
  instead of bare URLs (+6 links, and −8 penalty gone), and a pull quote
  (+3).

## Alignment with `docs/next-phase-plan.md` §1

The plan (#6) merged while this lane was in flight. The lane follows its own
brief, so the scorer matches the plan's contract but not its formula.

Matches the plan:
- The contract: pure text in, arena-only allocation, deterministic output,
  `density/1`, scores markdown and gfm only, and a doc with no format_check
  warnings never loses penalty points.
- Detection: callouts need a body line, only resolved footnote pairs count,
  tables are gfm pipe tables or HTML `<table>`.
- Signal names: `footnotes`, `fragment_links`, `callouts`, `wikilinks`,
  `embeds`, `frontmatter`, `tables`, `lists`, `links`, `styled_coverage`,
  `emphasis_variety`, `block_variety`.

Differs from the plan:
- **Formula.** Per-1000-word rates with a 200-word floor and a linear plateau
  curve, where the plan uses per-250-word rates with a 150-word floor and
  exponential saturation. Styled coverage gets full credit from 8% to 30% and
  none at 60%, where the plan's band is 15% to 25%, gone by 50%.
- **Weights.** Apparatus 63, Typography 18, Structure 19, where the plan has
  Apparatus 45, Structure 30, Inline 25.
- **Noise.** One `overload` tax (up to −20) for any signal past its `over`
  threshold stands in for the plan's `callout-confetti` and
  `heading-confetti` rules. The per-rule penalty values also differ, and
  there is no overall 40-point penalty cap.
- **Names.** Images count under `embeds`. Headings are split into
  `heading_levels` and `heading_density`. Quotes are `blockquotes`. Code is
  `code_fences`, and inline code counts as a styled run. `fragment_links`
  counts any link destination with a `#`, not only `#:~:text=`.
- **API.** `Score{total, words, signals, warnings}` instead of
  `Report{score, groups, components, penalties, kinds_used}`. There is no
  `measure()` and no `structureHash()` (§1.9).
- **Line model.** `density.zig` has its own scanner. Making formatcheck's line
  helpers `pub` was outside this lane's files.

Not built here: the §1.8 `corpus.json` / `expect.json` / ladder gate and
`density-eval`, the §6 small fixes, and the tool and CLI (D2).

If the captain adopts the plan's formula, the change is confined to the
`specs` and `penalties` tables and `curve()`; the scanner stays. Do it before
any model-matrix run, per the plan's calibration procedure.

## Known limits

- Setext headings, indented code blocks, and emphasis that spans lines are
  not recognized. k4o output and typical model output use none of them.
- Alphanumeric means ASCII only, so styled coverage ignores non-ASCII
  letters.
- A list or quote nested inside a callout counts toward the callout, not as
  its own block.
