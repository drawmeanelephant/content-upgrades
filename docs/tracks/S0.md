# S0: seams refactor

Goal: let many agents add tools to knap-mcp in parallel, with no behavior
change. See `AGENTS.md` for the resulting "add a tool" recipe.

## What changed

- **Tool registry.** `src/tools.zig` keeps `Tool`, `Error`, `Handler`,
  `all` (one line per tool), `dispatch` and `listJson`, and re-exports
  `templatePath`, `templateText` and `writeOutcome` with unchanged
  signatures. Each handler moved verbatim to `src/tools/<name>.zig`
  (`templates`, `validate`, `render`, `repair`, `lint`, `format_check`).
  Shared helpers (`getStr`, `requireStr`, `requireData`, `stageData`,
  `writeDiags`, `templatePath`, `templateText`) live in
  `src/tools/common.zig`. `writeOutcome` lives in `src/tools/repair.zig`.
  `eval.zig` and `mcp.zig` compile unchanged.
- **CLI table.** `src/main.zig` dispatches through `commands`, one row per
  subcommand: either a registry tool (`.tool`, `.key` for the first
  positional, plus `.exactly_one` / `.read_file` to keep the old
  `lint` / `format-check` behavior) or a `.custom` fn (`eval`, `backends`,
  `--help`, `--version`). The help text is generated from the rows and is
  byte-identical to the old one. String options forwarded to tools
  (`--target`, `--backend`) come from `tool_flags`, so a new one such as
  `--tone` is one entry. A comptime check in `main()` fails the build if a
  row names an unregistered tool or a name is duplicated. `serve` and the
  no-argument case still go straight to `mcp.serve`.
- **Backend.** `backend.Task = enum { repair, voice, verify, judge }` and
  `backend.complete(ctx, kind, task, system, user)` wrap the endpoint and
  model routing plus `chatCompletion`. `repairPatch` keeps its signature;
  its remote path now calls `complete(.repair, ...)`. `complete` refuses
  `.mock`. Every task uses the same model per backend for now. `Kind` is
  unchanged.
- **Test discovery.** One `test { _ = @import(...); }` block at the bottom
  of `src/main.zig` lists every file under `src/`.
- **Engines.** `scripts/engines.sh` holds the pins (k4o `f97c5db…`, dogbed
  `0c94175…`) and builds a missing pin from a `git archive` export in a
  temp dir under `~/.cache/knap-engines/`, then moves it into place as
  `<name>-<sha7>/`. Existing dirs are never rebuilt. Subcommands: `build`
  (default), `env`, `path <name>`. The Makefile adds `make engines`,
  exports `KNAP_K4O_PATH` / `KNAP_DOGBED_PATH` from the pins for every
  target (environment values don't override them; `make eval
  KNAP_K4O_PATH=...` does), and makes `eval` depend on `engines`.
- **AGENTS.md** at the repo root, plus the README "Layout" section.

## Findings

- **Before this change, `zig build test` ran 0 tests.** In a test build
  nothing in `main.zig` is referenced, so no other file was analyzed and
  the tests in `repair.zig` and `formatcheck.zig` never ran. The test
  binary printed `All 0 tests passed.` Now 4 run: 2 in `repair.zig`, 1 new
  in `tools/common.zig`, plus the discovery block itself.
- **`formatcheck.zig`'s tests leak.** Once discovered, all 8 pass but 7
  leak: `check()` is written for an arena and the tests pass
  `std.testing.allocator` without freeing. `make test` then fails. S0
  doesn't own `formatcheck.zig`, so its test-import line is commented out
  with the reason. Fix: give each test an `ArenaAllocator` (or free the
  result), then uncomment the line. Until then no test may call a tool
  handler, because the `knap_format_check` handler pulls those tests in.
  That is also why the registry and CLI guards are comptime checks in
  `main()` rather than tests.
- **engines.sh builds both pins from an archive.** Building into a
  throwaway `KNAP_ENGINES_DIR` took about 34 s, with dogbed's zig deps
  resolved from the local zig cache. The outputs are not byte-identical to
  the cached pins (the cached dogbed is a 4.3 MB binary copied from
  `zig-out`; the archive build is 1.3 MB ReleaseSafe), but they give the
  identical mock eval table and the same `render apparatus --target html`
  failure (`no filter named "wikilink"`). The existing
  `~/.cache/knap-engines/{k4o-f97c5db,dogbed-0c94175}` dirs stay as the
  accepted pins and were not touched.
- `zig fmt --check` already fails on `backend.zig` and `engine.zig` at
  `main`. Those pre-existing lines are left alone to keep the diff to the
  refactor.
- The eval `report:` line carries a timestamped doc_id
  (`doc-<ns>-<counter>`), so before/after comparisons normalize it.

## Gate evidence

- `make test` passes (4/4 tests).
- `make eval` table is identical before and after, apart from the doc_id.
- 45 CLI/MCP captures are identical before and after (doc_ids and temp
  paths normalized). They cover `--help`, `-h`, `--version`, `-v`,
  `templates`, `validate`, `render` (markdown, `--target=gfm`, textile,
  html, `--out`), `repair` (mock, `--backend=mock --target gfm`, spark
  without a key), `lint`, `format-check <doc_id>`, `backends`, `eval`, 20
  error paths, and two MCP sessions (`initialize`, `tools/list`,
  `tools/call`, `ping`, unknown method, `resources/read`, `serve`).
  Another 6 captures match too: stdin data, a baseten call to a closed
  local port through `complete()`, `KNAP_BACKEND=spark eval` without a key,
  `backends` with a key, and MCP tool errors.
