# Track C2: structure hash and the voice eval

## What landed

- `knap-mcp/src/structhash.zig`: `skeleton(alloc, doc, format)`, `skeletonOpts(..., .{ .strict = true })`, `hashTokens(tokens)`, `hashOpts(gpa, doc, format, opts)` and `hash(doc, format) u64` (Wyhash, seed 0, over the token kinds). Formats: markdown (k4o) and html (dogbed). It has 12 unit tests: text-only rewrites hash equal (table cells that change column widths, a heading whose html `id` changes, a frontmatter slug that follows the title), and each structural change hashes differently (one more list item, another heading level, a different or dropped callout, a different column count or alignment, a removed footnote, an injected `**`, an injected `\n- `, an extra or missing frontmatter key or list item).
- `knap-mcp structhash <doc_id|file>... [--target markdown|html] [--explain] [--strict]`: prints `<16 hex>  <name>` like sha256sum, one line per argument. `--explain` prints the tokens first, one per line, indented by depth. With no `--target` it uses the file or artifact extension, then sniffs.
- MCP tool `knap_structure_hash({doc_id, target?, strict?})` returns `{ok, doc_id, format, strict, hash, tokens}`.
- `knap-mcp/eval/voice/run.sh`, `apply-mock.jq` and `README.md`: the voice eval, described in that README.

Shared one-liners: a registry line in `src/tools.zig`, a `structhash` row in `commands`, one `usage_tail` help line, and two test-import lines in `src/main.zig`.

## Decisions

- **No second parser was shared.** The plan (next-phase-plan section 1.9) wanted the hash to reuse the density scorer's tokenizer. D1's tokenizer counts signals and doesn't emit an ordered kind sequence, and the brief said to keep structhash self-contained, so it has its own small block and inline parser. D2 can call `structhash.hash(doc, .markdown)` for the `structure_hash` field in `knap_density`.
- **It reads the subset k4o emits, not all of CommonMark.** It has no setext headings, no indented code blocks (indentation outside lists is ignored, which makes it whitespace-insensitive), no reference links and no lazy blockquote continuation. Lists, nested lists, callouts, pipe tables, footnotes and the CommonMark emphasis rules (flanking, intraword `_`, the rule of 3) are implemented.
- **It errs toward unequal.** A `**` or `_` run that could open or close but pairs with nothing becomes a `delim:` token, and bare `http(s)://` URLs become `rawurl`. A voiced `give a **shit` inside the template's `**...**` therefore changes the hash, even though the markdown still parses as one strong run. False "unequal" is a safe failure; false "equal" would make the demo claim a lie.
- **Frontmatter keeps shape only.** It records key paths, scalar vs list, list item counts and nested maps. Keys inside list-of-map items aren't tracked.
- **HTML drops the values of `href` and `src` by default**, to match markdown's default of dropping link targets. `--strict` keeps them. Attributes are sorted by name, and whitespace in class lists is normalized.
- **`hash(doc, format) u64`** matches the brief's signature by allocating from the page allocator, and it panics only on OOM. Code that has an allocator should call `hashOpts`.
- **Container nesting is capped at 64**, so a hostile doc can't exhaust the stack.

## For other lanes

- **Captain or P1 (Makefile):** please add this target:

  ```make
  voice-eval: all engines
  	knap-mcp/eval/voice/run.sh
  ```

  Add `voice-eval` to `.PHONY` too. The Makefile already exports the engine paths, and the script falls back to `scripts/engines.sh env` when run outside make.
- **C1 (`knap-mcp voice`):** the eval detects the command from a `  knap-mcp voice` line in `--help`. It runs `knap-mcp voice <id> -d <file> --tone <t> --backend mock` and compares `jq -S .data` with `eval/voice/apply-mock.jq`'s output, so the two must agree exactly: same matching on `(template, field path, input)`, misses left unchanged. If your guard rejects a mock reply, the eval reports a mismatch. Adding release-notes and reading-note lines to `prompts/voice/mock/*.jsonl` turns those rows on automatically. Lines for one template must exist in all three tones, or the row fails as `partial mock coverage`.
- **P1 (oliver target):** structhash doesn't read oliver. If oliver turns out to be markdown-like, it could probably map to `.markdown`; otherwise it needs its own tokenizer. `knap_structure_hash` refuses `.textile` and other unknown artifact extensions with a clear error.
- **D2:** `structhash.hash(doc, .markdown)` gives the `structure_hash` field the `knap_density` JSON sketch asks for.
- **dogbed (seen while testing, not fixed here):** frontmatter renders as `<hr/><p>...</p>` text, pipe tables come out as literal text in a `<p>` (known), and verdict's html drops the footnote definitions under `## Footnotes`. The hash covers whatever dogbed emits, so these don't affect equality, but the html skeleton will change when dogbed fixes them.
- **README / PARALLEL-PLAN (captain):** add `knap-mcp structhash` and `knap_structure_hash` to `knap-mcp/README.md`'s command and tool lists, and mark C2 as landed.
