# Track C3: voice tone presets

Content only, no Zig. Lane C1 loads these files from `knap_voice`.

## What landed

Everything lives in `knap-mcp/prompts/voice/` (see its README for the formats and the exact call assembly):

- `system.md`: the cache-stable system prefix. Rewrite one value; keep numbers, names, URLs, wikilinks, footnote markers, citation ids and quotes exact; add nothing; keep the verdict's direction and the hedges; add no markup or line breaks; stay within half to double the length; return only the string.
- `mild.md`, `spicy.md`, `feral.md`: tone guides with profanity, all-caps and `!` budgets. Feral is unhinged in delivery only, and it spells out the safety line (no slurs, no identity insults, no harassment).
- `examples/<tone>.jsonl`: 11 few-shot pairs per tone covering title, verdict, take, summary, bottom line, blockers, a receipts claim cell, footnotes and the apparatus subtitle. All three tones share the same inputs.
- `mock/<tone>.jsonl`: canned replies for the six `voice: true` values in the sample data, so C1's mock backend and C2's voice eval work without an API key.
- `voice.awk`, `check.sh`, `assemble.sh`, `testdata/bad.jsonl`: the guard, the gate, the reference prompt assembler, and 19 known-bad rewrites that prove the guard catches problems.

## Decisions

- **Examples use made-up subjects.** They are about QuuxQueue, NimbusCache and OrbitDesk Pro, never AcmeDB. Few-shot outputs built from the demo data would let the model copy them, and the voice demo would show memorized text. `check.sh` enforces this.
- **One system message per tone.** System prefix, tone guide and all examples go in the system message in a fixed order, so there are three cacheable prefixes in total. Only the user message (`Field`, `Role`, `Input`) varies per call. This fits the single `system`/`user` signature of S0's `backend.complete`.
- **The role comes from the shape.** `Role:` is the shape descriptor's `role` string, plus ` (one item)` for array elements. The shapes stay the single source of truth for eligibility (`voice: true`).
- **The guard is mechanical.** Fact preservation is checked by token extraction (URLs, wikilinks, footnote markers, quoted spans, number tokens, names), not by judgment. The same rules work as C1's runtime guard: a failing reply keeps the original value.
- **Lengths are in bytes.** `check.sh` sets `LC_ALL=C`, and Zig's `value.len` gives the same number.

## For other lanes

- **C1 (`knap_voice`)**: follow "Call assembly" and "The guard" in the README. `assemble.sh` prints the exact messages to test against. The mock backend can look up `mock/<tone>.jsonl` by `(template, field, input)`.
- **C2 (voice eval)**: the mock replies give three different strings for every voiced field, with zero API access.
- **Shape owners (T1, T2 or the captain)**: consider `"voice": true` on verdict's `blockers` and `footnotes` (the examples already cover them). `receipts` claim cells need a column-aware flag. Rewriting verdict's `title` leaves `frontmatter.title` unchanged, and rewriting release-notes' `title` changes its frontmatter `slug`; decide whether either `title` should drop its flag. Some T1 roles describe template mechanics (`??` fallbacks, slugs); they reach the model as the `Role:` line, so shorter page-facing roles would help.
- **Captain**: the SPEC and the README could point at `prompts/voice/` for the tone presets. I didn't touch either.
