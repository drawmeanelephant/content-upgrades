# B2: `knap_publish_check`

Status: done, PR open. `knap_publish_check` stages a rendered markdown doc
into a throwaway copy of the frozen boris site, runs `boris validate`, and
maps every diagnostic back to the rendered doc. It is a Zig port of
`boris-site/stage-check.sh --validate`, and `selftest.sh` checks that the two
agree.

Measured Oct 26 with `boris/0.8.2` (`~/.local/bin/boris`), k4o `bdfb838`,
Apple M4, macOS 27.2. Other agents were building on the same machine.

## Contract

MCP input `{"doc_id": "..."}`: a doc stored by `knap_render` or `knap_repair`.
Docs stored with any extension other than `.md` are rejected. Today that means
`html` and `textile`; see P1 below for oliver.

```json
{"doc_id":"doc-…","ok":false,"staged_as":"staged/doc-…","pages":22,"links":3,
 "diagnostics":[{"code":"EREFERENCEMISSING","severity":"error","line":37,"column":3,
   "detail":"wiki-link target \"acmedb-soc-2-audit-report\" not found in the page graph",
   "link":"[[AcmeDB SOC 2 audit report]]","target":"acmedb-soc-2-audit-report"}],
 "elapsed_ms":10.4}
```

- `ok`: false when any diagnostic has severity `error`.
- `staged_as`: the boris entity id of the staged copy, `staged/<doc_id>`.
- `pages`: pages in the staged site, the doc included. `links`: wiki-links
  plus embeds in the doc body. Frontmatter is dropped, so links in
  frontmatter are not counted.
- `line`/`column`: 1-based line and byte column in the **rendered doc**. 0
  means no position:
  - link diagnostics point at the `[[` (for an embed, the `[[` in `![[`);
  - other body diagnostics are shifted past the frontmatter rewrite;
  - frontmatter diagnostics point at the doc's title line, or its fences,
    with column 0;
  - `EROUTEMISSING` (boris reports these against the staged HTML) maps to
    the doc's `](href)`, with the column of the href;
  - diagnostics on other files (for example the `ELAYOUT` summary
    `target 'default' compilation failed`) get line 0. The file name is
    prefixed to `detail`.
- `link`: the original link text. An embed keeps its `!` (`![[…]]`), so a
  reader can tell a checked embed from a link. `target`: the entity id boris
  looked up, which is the slug for a rewritten link.
- `detail`: boris's message without the remediation. It is taken from
  stderr when that line matches, because the JSON message for
  `EROUTEMISSING` drops the href.
- `elapsed_ms`: time inside `check()`: stage, copy, boris, map, clean up.
- The tool fails (an MCP error, `ctx.err_msg`) for: an unknown doc, a doc that
  is not markdown, an unclosed frontmatter block, a missing site, boris not
  runnable, boris exit 2 or 3, or a missing report.

CLI: `knap-mcp publish-check <doc_id>` prints the JSON on stdout. **Exit 0 when
`ok`, 1 when not ok or when the check cannot run.** On a failure stdout is
empty and the reason goes to stderr. This is a `.custom` row
(`publish_check.cli`) that goes through `tools.dispatch`, so the CLI and MCP
share one code path.

Env, both listed in `--help`:

- `KNAP_BORIS_PATH`: the boris binary (default `boris` on `PATH`). A relative
  path containing `/` is made absolute, because boris runs in the staging
  dir.
- `KNAP_BORIS_SITE`: the site (default `<templates_dir>/../../boris-site`).
  B3 must use the same rule; `boris.siteDir(ctx)` is public.

Staging dir: `$KNAP_MCP_HOME/tmp/scratch-<ts>-<n>.boris/`, holding `content/`,
`themes/`, the doc at `content/staged/<doc_id>.md`, and `report.json`. It is
deleted on every path (`defer deleteTree`).

## `boris.check` for the demo lane (I1)

```zig
const boris = @import("boris.zig");
const r = try boris.check(ctx, doc_bytes, "verdict"); // name -> staged/verdict
// r.ok, r.staged_as, r.pages, r.links, r.diagnostics ([]boris.Diagnostic), r.elapsed_ms
```

It takes markdown bytes and does not need a doc_id; the caller checks the
format. The result is allocated in `ctx.arena`. On error, `ctx.err_msg` holds
the reason. Pure pieces with tests: `boris.stage(arena, doc)`,
`boris.slug(arena, s)`, and `boris.mapReport(...)`.

## The adapter: parity with stage-check.sh

The rules are the same as B1 §2, and `boris.zig` follows `stage-check.sh`
rule for rule:

- Frontmatter becomes `title` only. The title is double-quoted unless it
  contains `"`. With no title, the frontmatter is dropped. An unclosed block
  is an error.
- `[[T]]` becomes `[[slug(T)|T]]` and `[[T|L]]` becomes `[[slug(T)|L]]`.
  `#frag` is kept. Targets already in slug form (T2's
  `[[acmedb-docs-backups|AcmeDB docs — backups]]`) and empty slugs are left
  alone.
- The link matcher is the awk regex `\[\[[^]]+\]\]`: leftmost match, no `]`
  inside.
- Columns are bytes. A diagnostic at a link's staged (line, col) takes that
  link's doc position. Any other body line is shifted by `delta`.

**New rule, in both adapters: an embed is checked as a link.** Boris 0.8.2
cannot embed a page. `![[x]]` becomes an image whose src is `x.html`, and
`boris validate` rejects it with `EASSET` ("invalid or out-of-tree
content-local image path"). `boris check` passes it because it checks the
graph only. Without this rule, release-notes and reading-note can never pass
`validate`. The staged copy therefore drops the `!`. Only the target's
existence is checked; the embed is never rendered. Positions still point at
the original `[[`. `stage-check.sh` prints `(embed, checked as a link)` on
the mapping line.

What stays different, on purpose: `stage-check.sh` prints `EROUTEMISSING`
and frontmatter diagnostics without a doc position. publish-check maps them
where it can (see Contract).

## Gate

```text
$ make test                                   -> exit 0 (boris.zig: 6 tests, publish_check.zig: 1)
$ KNAP_MCP_HOME=$(mktemp -d) make eval        -> converged 5/18, no-op seeds 4, controls 3/3 (= main)
$ knap-mcp eval --corpus eval/seeds.2nap.json -> converged 36/179, no-op seeds 6 (= main)
$ zig build                                   -> no output
$ boris-site/selftest.sh
...
parity: ok   verdict.sample (exit 0) no diagnostics
parity: ok   apparatus.sample (exit 0) no diagnostics
parity: ok   release-notes.sample (exit 1) EROUTEMISSING@77:45,EROUTEMISSING@77:109,ELAYOUT@0:0
parity: ok   reading-note.sample (exit 1) EROUTEMISSING@22:96,ELAYOUT@0:0
parity: ok   verdict.hallucinated (exit 1) EREFERENCEMISSING@37:3
parity: ok   release-notes.hallucinated (exit 1) EREFERENCEMISSING@70:2
build.sh: artifact/ is current (boris/0.8.2)
selftest: ok
```

Parity means the same exit code and the same codes in order, plus the same
line:column wherever `stage-check.sh` maps one.

**release-notes and reading-note are not ok on main yet, and the cause is not
the wiki-links.** All their wiki-links and embeds resolve (selftest asserts
no `EREFERENCE*`). They fail on `EROUTEMISSING` because both templates still
use the pre-main `{{ "text" | link:url }}` argument order. On k4o `bdfb838`
that renders `[https://…](Full%20changelog)`, a link to a relative page that
does not exist. publish-check catches this broken link as a real defect.
With the k4o-main order (`{{ url | link:"text" }}`, applied to a temp copy of
the templates through `KNAP_TEMPLATES_DIR`), both samples are `ok: true`
with no diagnostics in publish-check and in `stage-check.sh --validate`. The
fix belongs to P1, which owns both templates.

| Case | median ms | min | max |

| `knap-mcp publish-check`, hallucinated verdict | 19.8 | 18.3 | 38.3 |
| `stage-check.sh --validate`, clean verdict | 52.3 | 44.9 | 100.9 |
| `stage-check.sh --validate`, hallucinated | 52.8 | 49.0 | 59.8 |
| `stage-check.sh` (boris check), clean | 45.7 | 41.2 | 50.2 |

The 21-page site plus the doc gives 22 pages. About 8 ms of the end-to-end
time is knap-mcp process start, ctx setup and the store lookup. About 5 ms
is `boris validate` (B1 §3). The rest is the in-process copy of 23 files.
