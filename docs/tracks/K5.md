## What changed

- `runner.zig`: on exit 0, each stderr line must parse as
  `k4o: warning <CODE> at line <L>, column <C>: <filter>: <detail>`.
  `CODE:filter` in order must equal `expected.warnings`. The position must
  land on `| <filter>` in the template, because the corpus has no positions
  and knap/k4o point at the filter name. New fail classes are
  `warning mismatch` and `misplaced warning`. Any non-warning line is still
  `stderr on success`. Exit-1 handling is unchanged. Case reports gain
  `warnings: ["CODE:filter@L:C", ...]` when there are any. Unit test:
  `test parseWarnings`.
- `run.sh`: `main` now reads `K4O_SHA` from `scripts/engines.sh` instead
  of hardcoding `bdfb838`. `results/k4o-main-bdfb838.*` is replaced by
  `results/k4o-main-aeba163.*`.
- `README.md` (conformance): headline, tables, failure list and the
  warning rules are updated.
