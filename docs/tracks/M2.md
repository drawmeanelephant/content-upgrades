# M2: the verifier slot (heuristic first)

`knap-mcp/src/verifier.zig`. SPEC layer 4 as a slot: `none | heuristic |
decision`. It is a loop gate and advisory only. It is never on the render
path, and its scores are not conformance metrics, so never put them next to
fixture counts.

**The heuristic is not NLI.** It is normalized string matching plus
content-word overlap. Only a verbatim quote earns `entails`. Everything else
is a guess from shared words, a negation word, and numbers.

## Signature changes from the brief

These are the only differences. D2 and later lanes should code against these:

- `checkCitation` returns `std.mem.Allocator.Error!Citation`. Running out of
  memory is the only error. A disabled, unavailable, or failing verifier never
  errors.
- `judgeStep(kind, before, after)` keeps three arguments. The caller passes
  "iteration budget spent" as `after.budget_spent` on `Step`.
- `StepVerdict` also carries `gain` (after − before density) and
  `new_warning` (the first new rule id, if any).
- `judgeStep` has one rule beyond the brief: if `before` had diagnostics and
  `after` has none and no new warning rule, it accepts. A repair that lands
  usually doesn't change density, and the brief's table would keep iterating
  forever. The ratchet never hits this rule, because its `best` state never
  has diagnostics.

## API

```zig
const verifier = @import("verifier.zig");

pub const Kind = enum { none, heuristic, decision };
verifier.parseKind("heuristic")                         // ?Kind

const c = try verifier.checkCitation(ctx, .heuristic, claim, &.{ quote_a, quote_b });
// c.label: .entails | .neutral | .contradicts | .unknown
// c.score: f32 0..1, c.reason: []const u8, c.matched: ?[]const u8 (the evidence item)

const v = verifier.judgeStep(.heuristic,
    .{ .density = 31.2, .warnings = &.{"raw-url-count"} },
    .{ .density = 38.0, .warnings = &.{"raw-url-count"}, .diagnostics = 0, .budget_spent = false });
// v.decision: .accept | .keep_iterating | .escalate, v.reason, v.gain, v.new_warning

verifier.heuristic(arena, claim, evidence)              // no Ctx needed
verifier.parseDecision(arena, reply)                    // ?Decision, strict
verifier.epsilon                                        // 1.0 density points
```

Everything is allocated in `ctx.arena` (or the arena you pass). `judgeStep`
allocates nothing, and its reasons are static strings.

## checkCitation

### `none`
Always `unknown`, score 0, reason `verifier disabled`.

### `heuristic`
1. **Normalize** the claim and each evidence item: lowercase ASCII, map
   curly quotes (`‘ ’ “ ”`) to straight ones and `…` to `...`, and collapse
   whitespace runs (including NBSP and line breaks) to one space. Quotes and
   final punctuation (`" ' . , ; : ! ?`) are trimmed off both ends of the
   claim.
2. **Verbatim.** If the normalized claim occurs in a normalized evidence item
   and starts and ends on word boundaries, the label is `entails` with score
   **1.0**, and `matched` is that item. `nap` doesn't match inside
   `snapshots`.
3. **Content words.** Text is split into runs of ASCII letters (inner
   apostrophes allowed) or runs of digits. A switch between letters and digits
   splits a run, so `2ms` gives `2` and `ms`. The tokenizer then:
   - drops about 80 stopwords;
   - maps number words `zero`…`twelve` to digits;
   - strips light suffixes (`-s`, a final `-e`, `-ing`, `-ed`), so
     `snapshots` matches `snapshot` and `acknowledged` matches
     `acknowledges`;
   - dedupes.

   A claim with no content words is `unknown`. So is a claim with no evidence.
4. **Overlap** is the share of the claim's content words found in an evidence
   item. The best item wins, and the first one wins a tie. The score is that
   overlap, capped at **0.95**, so 1.0 always means verbatim.
5. **Labels** for a non-verbatim claim:

| Condition (best evidence item) | Label |
|---|---|
| overlap < **0.6** (`high_overlap`) | `unknown` |
| overlap ≥ 0.6 and a negation mismatch | `contradicts` |
| overlap ≥ 0.6 and a number mismatch | `contradicts` |
| overlap ≥ 0.6 otherwise | `neutral` |

- A **negation mismatch** means exactly one side contains a negation word:
  `no not never without cannot none nobody nothing neither nor`, or any word
  ending in `n't`. That is the brief's list plus close kin.
- A **number mismatch** means the claim has a number the item lacks, and the
  item has a number the claim lacks (`19 seconds` against `9 seconds`). The
  brief doesn't include this rule. It catches the near-miss class, which is
  the classic fabricated-detail error.

The thresholds are pinned constants at the top of `verifier.zig`:
`high_overlap = 0.6`, `overlap_cap = 0.95`, `epsilon = 1.0`.

### `decision`
One `backend.complete(ctx, ctx.backend_kind, .verify, system, user)` call.
The system prompt asks for only `{"label":..., "score":...}`. The user message
is the claim plus numbered evidence. `parseDecision` is strict: after
trimming whitespace, the reply must be one JSON object with exactly the keys
`label` (one of the four names) and `score` (a number in 0..1). Fences, prose,
extra keys, or an out-of-range score all fail.

It falls back to the heuristic in each of these cases, and the reason says
which:

- `decision verifier unavailable (backend mock has no live completion); heuristic: …`
- `decision verifier unavailable (no MODEL_API_KEY); heuristic: …`
- `decision verifier unavailable (backend error: <msg>); heuristic: …` (`ctx.err_msg` is restored)
- `decision verifier unavailable (unparseable decision reply); heuristic: …`

When the model answers, the reason is `decision model (<backend>)` and
`matched` is null.

## judgeStep

The first matching row wins:

| # | Condition | Decision | Reason |
|---|---|---|---|
| 1 | `after.diagnostics > 0` | keep_iterating | `residual diagnostics` |
| 2 | a warning rule in `after` that is not in `before` | keep_iterating | `new format_check warning rule` (rule in `new_warning`) |
| 3 | `before.diagnostics > 0`, `after` has none | accept | `diagnostics cleared, no new warning rule` |
| 4 | `after.density − before.density ≥ epsilon` (1.0) | accept | `density gain >= epsilon, no new warning rule` |
| 5 | otherwise | keep_iterating | `density gain below epsilon` |

- When `after.budget_spent` is set, every keep_iterating becomes `escalate`
  and the reason gains `; iteration budget spent`. Accepted steps stay
  accepted.
- Warning comparison uses rule ids only. More hits of a rule that was already
  there do not count as new, because density already charges for them.
- `none` accepts every step (reason `verifier disabled`).
- `decision` has no Ctx in this signature, so it runs the heuristic table and
  prefixes the reason with `decision judge unavailable; heuristic: `.

## Tool and CLI (optional part, kept small)

`knap_verify_citation({claim, evidence: [..] | "..", verifier?, backend?})`
returns `{"verifier","label","score","reason","matched"}`. The CLI form takes
one evidence string:

```sh
knap-mcp verify-citation "AcmeDB shards its keyspace across nodes." \
    --evidence "AcmeDB does not shard. One node owns the whole keyspace."
# {"verifier":"heuristic","label":"contradicts","score":0.80,
#  "reason":"overlap 0.80 with evidence[0]; negation mismatch","matched":"AcmeDB does not shard. ..."}
```

## Gate: `knap-mcp/eval/verifier/`

`cases.json` holds 34 labeled pairs. Each one names its source: the
`data/*.sample.json` quotes and claims, and `boris-site/content/claims/` and
`sources/`. The classes are:

- `verbatim` (11)
- `paraphrase` (6)
- `negated` (7)
- `unrelated` (5)
- `near-miss` (5, each differing by one number)

`expected` is what a careful human would say. Two labels need defining:

- `neutral` means the evidence is on the same topic but neither confirms nor
  refutes the claim.
- `unknown` means the evidence doesn't bear on the claim.

The gate has two parts:

- **Zig test** (`make test`): the test `eval/verifier/cases.json: hard gate
  holds` fails the build if any verbatim case isn't `entails`, or any
  unrelated case isn't `unknown`.
- **Table:**

  ```sh
  cd knap-mcp
  zig run --dep verifier -Mroot=eval/verifier/gate.zig -Mverifier=src/verifier.zig -- eval/verifier/cases.json
  ```

  It prints the confusion table, per-class pass counts, and every miss. It
  exits 1 on a hard failure.

Results on this branch:

| expected \ heuristic | entails | neutral | contradicts | unknown |
|---|--:|--:|--:|--:|
| **entails** | 11 | 4 | 2 | 1 |
| **neutral** | 0 | 0 | 0 | 0 |
| **contradicts** | 0 | 2 | 9 | 0 |
| **unknown** | 0 | 0 | 0 | 5 |

Agreement is 25/34. By class:

| Class | Correct |
|---|--:|
| verbatim | 11/11 |
| paraphrase | 0/6 |
| negated | 5/7 |
| unrelated | 5/5 |
| near-miss | 4/5 |

The hard gate passes.

The misses, and why each one happened:

- **Paraphrases (0/6)** are by design: without a verbatim quote the heuristic
  never says `entails`. Four are `neutral`, which is the correct "same topic,
  unconfirmed" answer for a string matcher. `paraphrase-backup-gap` is
  `unknown`: the claim's words are spread across two evidence items.
  `paraphrase-one-node` is a **false contradicts**: the evidence item is "AcmeDB
  does not shard. One node owns the whole keyspace.", and the heuristic checks
  for negation per item, not per sentence.
- `negated-ack-order` ("acknowledged before fsynced") reverses the word order
  without a negation word, so it scores 1.00 overlap and comes out `neutral`.
  `negated-boots-old-key` ("boots fine" against "refuses to boot") has the
  same problem.
- `near-miss-snapshot-size` is a **false contradicts**. "Over 20 TB take hours"
  follows from "over 2 TB take hours", but the number rule doesn't understand
  monotone bounds.

## For other lanes

- **D2 (ratchet evidence slots):** gate on `c.label == .entails`. With the
  heuristic, that is exactly the plan's §2.6 "whitespace-normalized verbatim
  substring" rule. Put `c.reason` in the step's `verifier:` rejection reason.
  `neutral` is not grounded. Use `judgeStep` with
  `density = density.score(..).total` and `warnings` = rule ids from
  `Score.warnings`.
- **B3 (`boris_check`):** call `checkCitation(ctx, kind, claim, quotes)` on the
  retrieved quotes. `matched` is the quote to cite, and `grounded` is
  `label == .entails`.
- **P1 (owns `backend.zig`):** `verifier.zig` calls
  `backend.complete(ctx, kind, .verify, system, user)` and reads
  `ctx.environ.get("MODEL_API_KEY")` to decide availability. If either
  changes, `decide()` needs the same change.
- **Shared one-liners in this PR:** the registry line
  `tools/verify_citation.zig`, the CLI row `verify-citation`, the `tool_flags`
  entries `evidence` and `verifier`, two help lines in `usage_tail`, and
  test-import lines for `verifier.zig` and `tools/verify_citation.zig`.

## Known limits

- Overlap is a bag of words. Word order, scope, and who did what are
  invisible to it.
- Negation is checked per evidence item, so pass sentence-sized quotes. A
  double negative reads as "has a negation".
- The number rule doesn't handle bounds (`under 2ms` does entail
  `under 3ms`). It only knows number words up to `twelve`.
- Text handling is ASCII only: non-ASCII bytes split words, and only ASCII is
  lowercased.
- `judgeStep` in `decision` mode can't call a model: there's no Ctx in the
  signature. Adding one is a signature change that needs a note here first.
