# I3: density model matrix — `ratchet-eval` per live backend

Issue #91. Built on the `acp` backend (#130) and the LIVE harness (#154,
which produced the `devin-*` result profiles).

## What landed

- `knap-mcp/eval/ratchet.live.json` — the live-meaningful slice of
  `eval/ratchet.json`: every case whose `expect` does not depend on a
  per-case `mock` override. Nine rows: the four min rows (`release-notes`,
  `reading-note`, `verdict` — the verdict ratchet merged, so `verdict-min`
  is in — and `apparatus`), both sample rows, both fixture rows, and
  `iteration-cap`. The adversarial rows stay in `ratchet.json`; on a live
  backend they prove nothing (D2 "For other lanes"). `expect` blocks are
  copied verbatim, so a live run that misses the mock-tuned bar exits 1 —
  the FAILs below are model shortfall, not harness breakage.
- `knap-mcp/eval/results/live/` — raw outputs: `acp.txt` (stdout table),
  `acp.stderr.txt` (wall time), `acp.ratchet.json` (the stored
  `report: knap://docs/…` artifact with per-step detail), `mock.txt`
  (the same corpus on `mock`, kept as the control column), and the
  per-profile dirs `devin-wonder/` and `devin-swe-2/` written by
  `scripts/live.sh` (`ratchet.out` / `ratchet.err` / `provenance.json`).

## Why `acp` and not the sponsors

The issue names spark / wonder / baseten, but `MODEL_API_KEY` does not
exist yet — the key/credit issues #85 (Meta) and #86 (Baseten) are
`human-only` and still open. The `acp` backend needs no key, so the matrix
was run against `KNAP_ACP_AGENT='devin acp --agent-type summarizer'`
(devin 3000.11.3) and, via the LIVE harness, against devin's Muse
Wonder 1.0 and SWE-2 agents. When a sponsor key lands, rerun the same
command with `--backend spark|wonder|baseten` and append a column set —
the sponsor columns below are placeholders. The three `acp:` rows measure
model plus agent harness; they are not the direct-API sponsor numbers.

## Did it touch layout? — the `inert` column

**No. Zero inert rejections across all three acp runs — 53 calls (18
summarizer + 19 Muse Wonder + 16 SWE-2), inert 0 on every case.** The
new models' rejections went where the summarizer's did: mostly `schema`
(Muse Wonder 13 of 16 rejected calls, SWE-2 11 of 13; the rest are
declines). Every value that passed the schema gate also passed the inert
gate. Schema-rejected replies never reach the inert check, so the measured
failure mode is wrong-typed replies; layout-grabbing markup was not caught
once.

## What the `acp: summarizer` column says

- The summarizer answers scalar and low-structure asks well:
  `apparatus_page` (+10.5), `pull_quote` verbatim evidence (+2.4, passed
  the heuristic verifier), `callouts[+]` objects (two accepts),
  `aged[+]` (+12.7), `receipts[+]` (+5.7). Six accepts in 18 calls.
- **Schema rejections dominate** (11 of the 12 rejected calls; the other
  is a decline): table rows come back wrong-typed ("expected an object")
  and the `notes{+}` map append gets prose ("expected a string"). The
  agent summarizes instead of returning a single shape-typed JSON value.
- Consequence: `release-notes-min`, `reading-note-min` and
  `fixture-footnotes` stalled on iteration 1; `verdict-min`,
  `apparatus-min` and `iteration-cap` each banked one accept then
  stalled on iteration 2. `iteration-cap`'s FAIL is collateral — it
  spent its two iterations but the second asks both failed schema, so
  the stop is `stalled`, not `max_iterations`.
- Timing: ~4.3 s per `complete()` end-to-end, so the full 9-row corpus
  is ~77 s. At the `budget` cap (10 calls/case) a worst-case run is
  ~7–8 min; no case came close (max 3 calls).

## What the Muse Wonder / SWE-2 columns say

- Same shape, different models: both banked 3 accepts and both still
  fail most cases against the mock-tuned bar — Muse Wonder 2/9 `ok`,
  SWE-2 3/9 `ok` (the two sample rows plus SWE-2's `fixture-callouts`).
- Muse Wonder's gains are real but just short: `reading-note-min`
  +14.3 vs a 15.0 bar, `iteration-cap` +14.3 in 2 iterations. SWE-2
  repeats the summarizer's `verdict-min` +10.5 and gets
  `fixture-callouts` to +6.0 on 2 accepts.
- The rejection profile is unchanged: 24 of 29 rejected calls across
  the two runs are `schema`, 5 are `declined`; `parse`, `inert`,
  `render`, `verifier` and `no-gain` are all 0. Agent overhead is in
  these numbers too (~13k prompt tokens per turn, LIVE.md finding 3).
- Cost: Muse Wonder 90 s wall / 19 calls (~4.7 s/call), SWE-2 46 s /
  16 calls (~2.9 s/call) — same order as the summarizer's ~4.3 s/call.
