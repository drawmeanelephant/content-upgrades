## What landed

1. **Targets are `markdown | oliver | html`.** `engine.Target` drops the old two
   k4o formats. `oliver` runs `k4o render <tpl> --data <json> --format oliver` (the
   flag is in `k4o --help`: "markdown (default) or oliver"). Oliver output is still
   CommonMark: k4o's README says it differs only in `comment` (`<!-- -->`) and
   table delimiters (`| --- |`), and oliver reads it with `oliver render --from
   markdown < document.md`. So oliver docs are stored as `.md`
   (`engine.extension`). Schemas, error strings (`target must be
   markdown|oliver|html`), CLI help and the render description follow
   `engine.target_names`. MCP doc resources now carry a mime type from the
   artifact extension (`text/markdown`, `text/html`, `application/json`) in place of
   `text/plain` for everything.
2. **Mock patches read k4o main diagnostics** (`backend.zig`). `repair.zig` now
   passes the region's first line, so the mock maps the diagnostic's line and
   column (k4o counts columns in codepoints) into the region. Each rule fixes only
   what the diagnostic names at that position:

   | k4o main diagnostic | mock fix |
   |---|---|
   | `unclosed if/for block (missing ...)` | append the closer at EOF (unchanged) |
   | `no filter named "x"` | drop `\| x` **and its `:args`** (the old patch left `:"url"` behind) |
   | `expected a filter name after '\|'` (column = the token after the pipe) | drop that pipe: `{{ x \| }}` → `{{ x }}` |
   | `unclosed '{{' tag (missing '}}')` / `unclosed '{%' tag (missing '%}')` (column = opener) | close it at the end of the opener's line |
   | `unexpected text after condition` (column = text the tag swallowed) | close the nearest open `{{`/`{%` right before the column; if its closer sits later on the same line, move it there (`{{ name! }}` → `{{ name }}!`) |
   | `unexpected text in '{% endif %}'` | same, and the open tag must start with `endif` |
   | `unexpected '{% endif\|endfor\|else\|elseif %}' outside a(n) ... block` (column = after the keyword) | delete that tag (and its line if it stands alone) |
   | `unexpected '{% endfor %}' inside an if block` / `'{% endif %}' inside a for block` | swap in the enclosing block's closer |

   Patches splice by byte offset, so the old trailing-newline bug (line splitting
   wrote `\n` after the last empty piece) is gone. The old `unexpected text in output
   tag` key is still matched; k4o main no longer prints it. No rule reads a seed id
   or corpus text. 7 new unit tests cover the rules.
3. **No-op seeds: 0 in both corpora** (details below).
4. **`make eval` runs both corpora.**
5. **Link argument order.** `{{ url | link:"text" }}` in release-notes (2 links) and
   reading-note (1). Rendered markdown and html now put the text in the brackets and
   the URL in the parens (diff below).
6. **Optional items, both done.** `knap_repair` stores the repaired doc with the
   target's extension (`repair.Outcome` carries the target). curl reads the request
   body (`--data-binary @file`) and the `Authorization` header (`-H @file`) from
   0600 scratch files that are deleted after the call, so neither the prompt nor
   `MODEL_API_KEY` shows in `ps`. I smoke-tested this against a local fake
   OpenAI endpoint (`KNAP_BASETEN_URL`): the header and body arrived and the header
   file was removed.
7. **HTML check:** see below. With dogbed `a7f8c27` the tables are real `<table>`s.
8. **`format_check` is markdown only.** Markdown and oliver docs (`.md`) are linted
   as before. An html doc is refused with `format_check is markdown only: doc '<id>'
   is .html; render with target markdown or oliver`. The rules read markdown syntax
   (`#` headings, `[^n]` footnotes, `> [!x]` callouts, fences), so html would only
   produce wrong answers.
9. **Captain-assigned V0 bugs** (docs/tracks/V0.md, bugs 1 to 3), fixed here:
   the MCP `initialize` result was missing its closing `}` (now a unit test parses
   it); `File.writer()` does positional writes, so stdout redirected to a file
   overwrote from offset 0 (stdio now uses `writerStreaming`/`readerStreaming` in
   `main.zig` and `mcp.zig`); a render or validate returning `{"ok":false}` exits 1
   (JSON still goes to stdout). Checked: `echo initialize | knap-mcp | json.tool`
   parses, `{ echo AAAA; knap-mcp backends; } > f` keeps AAAA, broken render exits 1,
   good render exits 0. The `main.zig` edits outside the help line were assigned by the
   captain's note.

## No-op seeds

k4o main is more lenient than the old pin. Probed on `bdfb838`:

- `{{ x | f: }}` (empty argument) is accepted by every filter whose argument is
  optional (`wikilink:`, `h2:`, `bold:`, `list:`). It fails only on filters that
  require one (`yaml_property:`, `truncate:`).
- `footnote` ignores any arguments (`footnote:"1"`, `footnote:"1","2"`).
- `callout` with no argument defaults to `info`. Callout tuples resolve variables
  (`("note", x)`), and extra tuple members are ignored.
- `link`'s text is optional: `{{ url | link }}` gives `[link](url)`.
- `code:"x"` sets the language and `table:(...)` sets headers. `codeblock` and
  `numbered` no longer exist.

**seeds.json** (each one replaced, same class):

| old seed | why it was a no-op | new seed | break | k4o main error |
|---|---|---|---|---|
| wikilink-bad-arg (empty-filter-arg) | `wikilink:` = no alias | yaml-property-empty-arg | release-notes `yaml_property:"codename"` → `yaml_property:` | `filter 'yaml_property' requires one non-empty property name` |
| footnote-extra-arg (bad-filter-arg) | footnote ignores args | heading-extra-arg | verdict `{{ "Footnotes" \| h2 }}` → `h2:"1"` | `filter 'h2' takes at most 0 argument(s)` |
| callout-missing-arg (missing-filter-arg) | bare callout defaults to info | yaml-property-dropped-arg | release-notes `yaml_property:"version"` → `yaml_property` | `requires one non-empty property name` |
| callout-variable-in-tuple (bad-filter-arg) | tuples resolve variables | bold-extra-arg | verdict-callout `{{ label \| bold }}` → `bold:"strong"` | `filter 'bold' accepts '_' or no argument` |

`yaml_property` is the only shipped filter whose argument k4o main requires, so the
two argument classes now run on release-notes. I tried `callout:(note, "The take")`
(unquoted type) as a callout-specific break. It errors, but only because of a k4o
tuple-parser quirk (`("note", x)` is fine, `(x, "y")` is a syntax error), so I left it
out because a k4o fix would turn it back into a no-op.

**seeds.2nap.json** was regenerated (2nap `38b2ffc`), not hand-edited. Generator
changes against the E1 appendix are in the diff below. Results: 167 breaks plus
2 controls, all from 41 triples. The 18 removed seeds:

- 6 no-ops: `filter-code-basic`, `filter-table-basic` and `ex-table` `/bad-filter-arg`
  (code and table take an argument on main, so NOARG drops them; those templates have
  no other no-arg filter); `filter-link-basic/missing-filter-arg` and
  `/empty-filter-arg` (link text is optional, so NEEDARG is now empty);
  `err-bad-args-link-missing` (moved to `error_cases_skipped` for the same reason).
- 12 seeds on 3 triples whose base template no longer renders (`codeblock`,
  `numbered` x2). They were broken before any mutation: the old run printed "base
  template does not render clean" for each. The generator now gates triples on
  "renders clean under pinned k4o main" because k4o main can't reproduce 2nap's
  expected textile, so the old byte-exact gate can't run. As a safety net it also
  drops any mutation that renders clean and records it in
  `provenance.mutations_dropped` (empty in this run).

Note: `filter-link-basic` still renders on main, but with its arguments reversed
(`{{ name | link:"https://…" }}` now means text = URL). It stays because the seeds
on it test tag syntax, not link semantics.
