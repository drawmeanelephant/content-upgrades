### format-check warnings on the textile render (justified)

`knap_format_check` reads Markdown only. On a Textile doc it:

- counts `"text":https://…` Textile links as bare URLs (`raw-url-count`), and
- does not recognise `h1.`/`h2.` headings, so it reports `heading-ratio`.

Neither applies to Textile. The markdown and gfm renders of the same data are
clean. Fix belongs to whoever owns `src/formatcheck.zig`: skip or adapt
these two rules for `.textile` docs.

### HTML target

`render --target html` fails for both new templates with
`unknown logic tag 'set'`: dogbed-0c94175 bundles a k4o older than `{% set %}`
(and older than `wikilink`, the known failure for `apparatus`). Lane K2's
dogbed bump fixes both. Nothing to change in the templates.

## k4o behaviour learned the hard way (useful for T2, C1, E1)

- **Filter args resolve top-level data keys only, never `{% set %}`
  variables.** `{% set alt = cover_alt ?? title %}{{ cover | image:alt }}`
  emits the literal alt text `alt`. Consequences:
  - per-item URLs inside a `for` loop cannot be linked (`link:s.url` is a
    syntax error, a set variable is taken literally). That is why `verdict`
    prints bare URLs. The new templates link only top-level URLs and use
    wikilinks for per-item references.
  - optional-arg fallback needs `{% if %}…{% else %}`, as `release-notes`
    does for `screenshot_alt`.
- **Callout tuples take quoted strings and `true`/`false` only.**
  `callout:(kind, "T")` is a syntax error, so callout kinds and titles are
  template-owned by construction.
- **`a ?? b | f` parses as `a ?? (b | f)`.** To fall back and then filter, bind
  first: `{% set cn = codename ?? "…" %}{{ cn | yaml_property:"codename" }}`.
- **`yaml_property` on a missing key emits `key: null`.** Use `{% if %}` or a
  `??` fallback for optional frontmatter keys.
- **`footnote` slugs object keys exactly like `kebab`** (`"Mr. Kuno's Point!"`
  → `mr-kuno-s-point`), so `[^{{ note | kebab }}]` always matches its
  definition. Strays show up as format_check `unresolved-footnote` /
  `unused-footnote`.
- **`x | wikilink | list` in markdown escapes the brackets**
  (`- \[\[Alpha\]\]`), which breaks the wikilinks. Textile is fine. Link
  clouds here use a loop with a `·` separator instead. Worth a k4o issue.
- **A missing key used as a bare arg becomes a literal.** If a model drops
  `changelog_url`, `link:changelog_url` links to the relative path
  `changelog_url` without any error. The shapes mark these keys required; a
  verifier or publish_check could flag links whose target equals a key name.
- **`fragment_link` does not percent-encode `-`** in the text directive (the
  Text Fragments spec asks for `-`, `,` and `&`). A hyphen inside a single
  term is not a prefix/suffix marker, so `first-hand` should still match
  (not browser-tested). Also, the URL arg must not already
  carry a `#fragment`: k4o appends `#:~:text=`, giving `…#a#:~:text=`.
- **Loop whitespace differs by target.** Markdown trims one trailing newline
  per loop body and joins iterations with `\n`; Textile concatenates bodies.
  Putting the between-items separator behind `{% if not loop.last %}` makes
  both targets identical (documented in each template's header comment).
